# Learning diary

Maintain `DIARY.md` at this repository's root. This skill applies only to this
project; do not create or update diaries in other repositories.

Before finishing relevant work, identify whether it established a new AI
engineering concept, application, tradeoff, or finding. A failed experiment or
an evidence-backed investigation can qualify; a plan or routine code change
alone does not. If nothing qualifies, leave the diary unchanged.

Read the existing diary and the evidence relevant to the lesson: work completed
in the conversation, code, experiment results, or project notes. Record only
what that evidence supports. Distinguish implemented capabilities, measured
outcomes, and open hypotheses; never claim a quality improvement just because
a feature was implemented. Do not run paid evaluations just to write an entry.

Update automatically without asking for permission:

- Group entries under `## YYYY-MM-DD`, newest dates first. Use the user's local
  date for current work; when seeding older lessons, use a documented date or
  label them as a current-date recap rather than inventing history.
- Write one bullet per meaningful topic: `- **Topic:** Lesson and how progress
  was made.` Aim for one sentence of about 20–30 words, excluding the topic
  label. Keep only the core lesson and how it was learned or applied.
- Prefer concrete concepts and findings over task lists, implementation logs,
  long explanations, or duplicated topic indexes. Add a short relative link
  only when it materially helps explain or support the lesson.
- Preserve earlier entries. When a topic advances on another date, append a
  new entry explaining the new learning. On the same date, consolidate related
  findings into its existing bullet without losing the lesson.
- Avoid repeating a lesson merely because it was discussed again. Do not
  rewrite historical conclusions to imply that later findings were known then.

Review the change for brevity, factual support, and duplication. Whenever the
diary changes, explicitly mention `DIARY.md` in the final response, link to it,
and briefly name the topics added or updated. Do not claim an update if the
file did not change.
